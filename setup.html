Debagr

Install to first deployment

This guide covers Debagr 0.3.0, a technical preview for Apple-silicon Macs. Managed remote deployment needs macOS 26 or later on the Mac. The preview is free for personal and internal evaluation and may not be redistributed.

Set up the Builder

The Builder is the Mac that builds your app, owns the Apple pairing with your device and runs the deployment. Everyday wireless deployment needs only this one Mac.

  1. On the Builder, install current Xcode and Debagr: brew install --cask radeknovis/debagr/debagr.
  2. Pair your iPhone or iPad with the Builder over USB, grant trust, enable Developer Mode, and test a local signed build.
  3. Connect the Builder and the device to your private VPN. Keep the device nearby on the same Wi-Fi for this step.
  4. Click the Debagr icon in the menu bar and choose Open Debagr. With no saved device, the Connections window opens on Use existing pairing. Select the paired device and choose Continue. Select your VPN provider, the device's VPN address and its nearby service, then choose Continue. Confirm that the selections refer to the same physical device and choose Save & check connection.
  5. Leave Debagr running in the logged-in Mac session. Enable Launch at Login if you want it to start with the Mac. Move the device to another Wi-Fi network and keep it unlocked with the VPN connected. Cellular-only operation is unsupported.

Deploy

  1. Download the matching Claude Code or Codex plugin ZIP from Releases. Extract it and follow its included README installation instructions.
  2. Run /Applications/Debagr.app/Contents/MacOS/Debagr --devices --json on the Builder. Select the intended Apple identifier, then run --status --device <UDID> --timeout 30 --json.
  3. Build a signed device .app on that Mac, or copy the complete signed artifact there. Run readiness again after building, then --deploy-app /absolute/path/App.app --device <UDID> --launch --json. Allow 180 seconds. Report success only when installed and launched are both true.

For a remote agent, use your existing SSH access as the same Mac user. The plugin does not set up SSH, signing or Apple trust.

On failure, run --diagnose --device <UDID> --timeout 30 --json and follow its recovery instruction. An installation timeout has an unknown outcome; run --installed-apps --device <UDID> --json before retrying. If only the launch failed, run --launch-app <bundleID> --device <UDID> --json instead of reinstalling.

Builder and Client

Debagr names two roles for a Mac. The Builder compiles apps, holds the Apple pairing and deploys. A Client is a second Mac that has the device plugged in by cable. You need a Client only when the Builder is somewhere you cannot bring the device, and only to create the first Apple trust.

A role is saved when you link two Macs on the Initial device pairing screen. Debagr listens for other Debagr Macs on your private network (TCP 49388 and 49389, with Bonjour advertisements) only while that screen is open, while a role is saved on the Mac, or while you run debagr --usbip discover or debagr --usbip advertise yourself. Two Macs link without a code only when Tailscale reports that the same Tailscale user owns both. In every other case both Macs show a pairing code that you compare before accepting.

Experimental USB pairing

In the Connections window, the path picker also offers Initial device pairing. It is labelled Experimental. It forwards USB from a Client to the Builder so that the Builder can pair with a device that is plugged into the Client. From that screen, Use VirtualHere instead… opens the VirtualHere variant.

Requirements before you start:

  • Two Macs running Debagr 0.3.0, one as Builder and one as Client.
  • A USB tool that you install separately: a patched Longcable server on the Client plus usbip-macos on the Builder, or VirtualHere on both Macs.
  • For USB/IP, an administrator password on each Mac and System Integrity Protection turned off on the Builder. Turning it off lowers that Mac's protection; turn it on again when you finish.

No USB path and no two-Mac link has passed hardware acceptance. If you can connect the device to the Builder by cable once, do that and stay on the Use existing pairing path.

Verified and not yet verified

Verified on hardware: one remote iPhone installation and OS-confirmed launch over Tailscale on 10 November 2026 with a 0.3.0 candidate build. A confirmed launch is not a test of the app's interface.

Not yet verified for 0.3.0: first launch on a clean Mac, first launch offline, iPad, recovery after restart, sleep and wake, a network change, revoked trust or denied Local Network permission, VPN providers other than Tailscale, macOS 13 to 15, the Homebrew upgrade from 0.2.0 to 0.3.0, and all hardware use of USB/IP, VirtualHere and two-Mac Builder/Client linking.
