Privacy

Debagr has no analytics, advertising, crash SDK, customer account, or Debagr cloud. Nothing is sent to the publisher. On the build server it processes visible device names, identifiers, app paths and bundle identifiers, deployment results, macOS version, developer-tools availability, and optional Tailscale status.

Builder/Client setup. Linking two Macs uses peer discovery on TCP port 49388 (Bonjour _debagr._tcp) and role pairing on TCP port 49389 (Bonjour _debagr-role._tcp). These services do not start at launch. They run only while the Initial device pairing screen is open, or while a Builder or Client role is saved on that Mac. The commands debagr --usbip discover and debagr --usbip advertise also start them while the command runs. To switch them off, choose Show Diagnostics, then Unpair This Mac, and close the window.

While they run, they listen on all IPv4 interfaces and answer only the Mac itself, private network addresses, and the 100.64.0.0/10 range used by Tailscale. Any device on the same private network or VPN can read, without authentication:

  • the protocol version and a random node ID generated by Debagr;
  • the Mac’s name;
  • which Debagr processes are running (the app, a USB export process, a USB import process);
  • the saved role (Builder, Client, or none) and the node ID of the paired Mac;
  • the Mac’s public key for role pairing.

Whether System Integrity Protection is on or off, and the product names of plugged-in Apple devices (for example “iPhone”), are sent only to the Mac itself and to a device that the local Tailscale client confirms is owned by the same Tailscale user. Serial numbers and device identifiers are never sent.

Scan for other Macs. When you open or refresh that screen, Debagr browses Bonjour on the local network, runs tailscale status on your Mac, and connects to every online peer in your tailnet on TCP ports 49388 and 3240 to find Debagr and running USB/IP servers. Macs it has found are contacted again about every five seconds while the services run.

Linking Macs. Two Macs link without a pairing code only when the Tailscale network map shows that both belong to the same Tailscale user. Tagged devices, other users’ devices in a shared tailnet, and local-network connections show a pairing code on both Macs to compare first.

Temporary USB sharing. The experimental USB/IP path sends the selected device’s USB traffic from the Client Mac to the Builder Mac without encryption of its own; use it only across your VPN. It starts a USB tool as root, only after you approve the macOS administrator prompt. The VirtualHere path uses your existing SSH access to fetch the device’s connection profile from the Client Mac to the Builder. Debagr stores no passwords or SSH credentials.

Stored data. Connection profiles and the last deployment receipt persist under ~/.config/debagr/. Profiles include device identifiers, VPN endpoints, and captured local service metadata. The role-pairing signing key and the folders and logs of USB setup connections persist under ~/Library/Application Support/Debagr/. The saved role, the paired Mac’s public key, and the selected USB tools are kept in the com.debagr.app preferences.

Diagnostics. A diagnostics report goes to the clipboard and leaves the Mac only if you paste and send it. Reports can include device names, Mac names, hostnames, private addresses, and ports. Review them before sharing.

Support

  1. Confirm Xcode and devicectl are installed on the build server.
  2. Pair over USB, trust that Mac, and enable Developer Mode.
  3. Keep the device unlocked for the first install.
  4. Confirm the signed device .app exists on the build server.
  5. Test the Debagr command locally before invoking it through SSH.
  6. Choose Copy Diagnostics, review the result, and share it only through private reporting, below.

Contact

Report problems in GitHub Issues with the exact macOS, Xcode, and iOS versions. Never post device identifiers, hostnames, VPN addresses, pairing material, or diagnostics in a public issue.

Send security vulnerabilities, privacy requests, and requested diagnostics through GitHub private vulnerability reporting. Support is best effort during the technical preview.

Uninstall

If a USB/IP setup connection is running, choose Stop Setup Connection first; it keeps running after the app quits. Turn off Launch at Login, quit Debagr, and move the app to Trash. Run defaults delete com.debagr.app to remove the preferences, including the saved role and the paired Mac’s key. To discard all saved data as well, back up any profiles you want to retain, then remove ~/.config/debagr/ and ~/Library/Application Support/Debagr/. This does not revoke Apple pairing, uninstall deployed apps, or remove separately installed USB tools. A Mac that was linked to this one keeps this Mac’s public key until you choose Unpair This Mac there.
